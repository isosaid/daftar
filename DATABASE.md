# Структура базы данных

База — один JSON-объект. Хранится в браузере (`localStorage`, ключ `daftar-v2`),
выгружается кнопкой «Скачать копию», загружается кнопкой «Загрузить копию».
Сервер не нужен: файл `data/empty.json` — чистая база, `data/demo.json` — пример.

## Корень

```jsonc
{
  "active": "main",        // id активного бюджета
  "budgets": { ... },      // словарь бюджетов: id -> бюджет
  "tasks": [ ... ]         // задачи планерки — общие для всех бюджетов
}
```

## Бюджет (`budgets[id]`)

| Поле    | Тип     | Описание |
|---------|---------|----------|
| `name`  | string  | Название: «Личный», «Семейный», «Проектный» |
| `roll`  | bool    | Переносить остаток на следующий месяц |
| `start` | number  | Стартовый остаток при создании бюджета |
| `resets`| object  | Точки обнуления: `{"2026-09": 0}` — с этого месяца счёт идёт заново |
| `cats`  | array   | Конверты (статьи расходов) |
| `goals` | array   | Накопительные цели |
| `tx`    | array   | Операции |

## Конверт (`cats[]`)

| Поле    | Тип    | Описание |
|---------|--------|----------|
| `id`    | string | Уникальный ключ, на него ссылается `tx.cat` |
| `name`  | string | «Еда и другое», «Хайр» |
| `color` | string | HEX-цвет заливки |
| `plan`  | number | Месячный лимит в сомони; `0` — без лимита |

## Операция (`tx[]`)

| Поле     | Тип            | Описание |
|----------|----------------|----------|
| `id`     | number         | Timestamp создания |
| `type`   | `in`/`out`/`save` | Доход / расход / в накопительную цель |
| `cat`    | string \| null | Конверт — только для `out` |
| `goalId` | string \| null | Цель — только для `save` |
| `desc`   | string         | Описание |
| `amt`    | number         | Сумма, сомони |
| `date`   | `ГГГГ-ММ-ДД`   | Дата операции |

`save` — это не расход. В балансе месяца три отдельные строки: доход, расход, в цели.

## Цель (`goals[]`)

| Поле     | Тип          | Описание |
|----------|--------------|----------|
| `id`     | string       | Ключ, на него ссылается `tx.goalId` |
| `name`   | string       | «Ноутбук» |
| `target` | number       | Сколько нужно накопить |
| `due`    | `ГГГГ-ММ-ДД` | Срок; пустая строка — без срока |

Накопленное не хранится — считается суммой операций `save` с этим `goalId`.
Так цифра не может разойтись с историей операций.

## Задача (`tasks[]`)

| Поле    | Тип                          | Описание |
|---------|------------------------------|----------|
| `id`    | number                       | Timestamp |
| `title` | string                       | Название |
| `mod`   | string                       | Модуль — направление работы, группировка в отчёте |
| `who`   | string                       | Исполнитель |
| `due`   | `ГГГГ-ММ-ДД`                 | Срок |
| `st`    | `open`/`work`/`hold`/`done`  | Статус |

Просрочка не хранится: задача просрочена, если `st !== "done"` и `due < сегодня`.

## Расчёты

```
точка обнуления = последний ключ resets, который <= текущего месяца (иначе нет)
база            = resets[точка] если есть, иначе start
перенос         = база + Σ(in) − Σ(out) − Σ(save)
                  по операциям от точки обнуления до текущего месяца, если roll = true
доступно        = перенос + доход − расход − в цели  за текущий месяц
остаток конверта = plan − Σ(out по этому cat за месяц)
накоплено по цели = Σ(save по этому goalId)
```

## Хранение

Ключ `daftar-v3`. Старые ключи (`daftar-v1`, `daftar-v2`) не читаются:
приложение всегда стартует с пустой базы. Данные из прежних версий
переносятся вручную — «Скачать копию» в старой версии, «Загрузить копию» в новой.

Кнопка «Очистить всё» стирает и текущий ключ, и все прежние.

## Обнуление месяца

Три независимых способа начать с нуля:

| Способ | Что делает | Где |
|--------|-----------|-----|
| `roll: false` | Каждый месяц считается отдельно, перенос выключен навсегда | «Доступно» → переключатель |
| `resets["2026-09"] = 0` | Именно этот месяц стартует с нуля, прошлые месяцы остаются как есть | «Доступно» → «Начать этот месяц с суммы» |
| `resets["2026-09"] = 2000` | Месяц стартует с указанной суммы — например, реальный остаток в кошельке | там же |
| удаление операций месяца | Записи месяца стираются, перенос из прошлых месяцев остаётся | «Доступно» → «Удалить операции месяца» |

Обнуление задаёт новую точку отсчёта: следующие месяцы считают перенос от неё,
а не от начала истории. Удаляется одной кнопкой «Вернуть перенос».
